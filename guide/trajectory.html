轨迹数据：一个移动的点，被按时记录

上一课解决了"一个坐标是什么"。这一课解决"一整条轨迹是什么"。 一句话：轨迹 = 一辆车在不同时刻的位置点，按时间排成一行一行。 每一行叫一条记录，包含"谁、几点、在哪"，有的还带"开多快、载没载客、加速度多少"。

轨迹的最小单元：一条记录

从北京数据集里随便抽一行，真实数据长这样：

1,2008-02-02 15:36:08,116.51172,39.92123

用逗号拆开，四个字段依次是：

  • 1 — 出租车 ID：这辆车是谁。
  • 2008-02-02 15:36:08 — 时间戳：什么时候记录的。
  • 116.51172 — 经度：东西方向在哪。
  • 39.92123 — 纬度：南北方向在哪。

把同一辆车的记录按时间连起来，就是一条轨迹。下图示意"点 → 线"的过程：

常见字段逐一拆解

三个数据集字段不同，但万变不离其宗。下面把可能出现过的字段都讲一遍—— 每个字段都不是白给的，它对应一个能回答的问题：

  • taxi_id / id 车辆唯一标识。作用：把"一堆点"还原成"一辆车的轨迹"。没有它，所有点混在一起只是噪音。 1 / 0086627503166932
  • timestamp 记录时刻。作用：给点排序、算速度、看早晚高峰。轨迹分析里时间与空间同等重要。 2008-02-02 15:36:08
  • longitude / lon 经度（WGS-84 小数度）。作用：东西方向坐标，配合纬度确定空间位置。 116.51172
  • latitude / lat 纬度（WGS-84 小数度）。作用：南北方向坐标。 39.92123
  • speed 瞬时速度（km/h）。作用：判断堵不堵、是否高速行驶。注意它来自 GPS 测速，不是车辆码表。 19 / 80
  • passenger 载客状态（0=空车，1=载客）。作用：区分"空车巡游找客"和"载客运营"——这是深圳数据独有的宝贝。 0 / 1
  • 方向 航向角（0-360°，正北为 0°）。作用：判断行驶方向、是否掉头。90°=正东，180°=正南。 121
  • 纵向/横向/垂直加速度 三个方向的加速度（cm/s²）。作用：判断急加速/急刹车/颠簸。是驾驶行为分析的原料。 1202 / 315 / 120
  • 横摆角速度 绕垂直轴旋转的角速度（deg/s）。作用：转弯有多急。配合速度可识别弯道超速。 343
🧭
字段越少 → 能做的问题越基础；字段越多 → 能做的分析越深

北京只有"谁/几点/在哪"4 个字段，适合做空间分布、轨迹聚类； 深圳加了速度和载客状态，能做运营效率分析； 无锡的 9 维信号则足以支撑驾驶行为识别。

采样间隔：精细 vs 成本的权衡

三个数据集的采样间隔差别很大，这不是巧合，而是当时技术成本的体现：

数据集采样间隔意味着什么
北京 2008~10 分钟车从东城开到西城之间只有 1-2 个点，轨迹是"粗线条"
深圳 2014~90 秒一个路口等红灯能记 1-2 个点，能分辨大部分街道走向
无锡 2020~1 秒秒级采样 + 惯性信号 = 能还原加减速的每一帧，像"行车记录仪"
💡
为什么不是越密越好？ 采样越密，GPS 盒子功耗越大、存储与上传成本越高、无用数据（静止时的重复点）也越多。 2008 年一辆车一天只有几百个点；2020 年秒级数据一天上万个点。 选什么间隔，取决于你要分析什么：看通勤格局，10 分钟足够；看急刹车，必须秒级。

数据质量：真实数据的"瑕疵"与对策

真实数据不是教科书里的完美表格。项目里三个数据集都暴露了同样几类问题，处理它们是分析的第一步：

问题表现常见原因处理方式
重复记录 同一时间同一位置出现两次 GPS 抖动 / 设备重发 按 (时间, 坐标) 去重
静止点堆积 长时间坐标几乎不变 等客、停车、交班 识别停留点（stay point）单独分析
坐标越界 点跑到城市外甚至别省 设备故障 / 数据混入 按城市经纬度范围过滤
字段缺失/错位 一行只有部分字段 导出格式问题 丢弃或补全（见无锡 README 日期不一致）
📌
本项目的真实案例：北京 1 号车从 21:40 起坐标几乎不再变化 （116.6916, 39.8517 附近），直到凌晨——这就是典型的静止点； 无锡数据里出现 112.44°E / 34.82°N 的坐标（远在河南），明显是越界脏数据。 这些都不是"错误"，而是真实世界的痕迹，处理它们本身就是分析能力。

👉 想看每一种瑕疵具体长什么样、怎么检测，见 《模拟数据集图鉴》—— 那里用 12 个小型模拟数据集，把这类数据所有可能出问题的情况逐一演示了一遍。

数据质量的四个维度（评估任何轨迹数据集的模板）

判断一份轨迹数据"能不能用、怎么用"，可以套一个通用的四维框架。这个框架不只适用于出租车数据， 任何时空序列数据都能用它来体检：

维度问的问题在轨迹数据上的体现本项目实例
完整性
Completeness		 该有的字段/记录有没有缺失？ 字段是否齐全；是否存在大段时间空白 无锡有 9 维信号但行驶段 IMU 是常量（字段有、内容空）；深圳缺失方向角
准确性
Accuracy		 坐标/数值是否贴近真实？ 越界点、漂移、常量占位、假速度 无锡 11.7% 跨省份越界；无锡行驶段 IMU 恒为 1202/315/120/343
时效性
Timeliness		 时间戳是否可信、一致？ 时区混乱、日期格式不一、跨日截断 部分导出文件日期标 2020 但 README 写 2022；混合时间戳格式
一致性
Consistency		 同一概念是否用同一方式表达？ 分隔符混用、单位不一、编码差异 无锡 CSV 首列后带制表符再逗号（混合分隔符）
🧭
怎么用这个模板？ 拿到任何一份新轨迹数据，先用这四问快速"体检"：缺字段吗（完整性）、有越界/常量吗（准确性）、 时间对得上吗（时效性）、格式统一吗（一致性）。哪一维不过关，就针对性清洗。 下一节的《模拟数据集图鉴》正是按这四个维度，把每种"不过关"的样子都造了一份样本给你对照。

小结

  • 轨迹 = 按时排序的位置点序列；一条记录 = 谁 + 几点 + 在哪（+ 更多）。
  • 采样间隔决定轨迹的"分辨率"，是技术成本的体现，不是随意选的。
  • 每个字段对应一个可回答的问题——读数据时先问"这个字段能帮我回答什么"。
  • 真实数据有重复、静止、越界、缺失四类通病，清洗是分析的第一步。
