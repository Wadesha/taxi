把静态站推到 GitHub Pages

本项目是纯前端静态站（HTML/CSS/JS + PNG 图片），不需要后端、不需要构建。 部署到 GitHub Pages 只需"仓库初始化 → 推送到 main 分支 → 在仓库设置里启用 Pages"三步。

为什么是纯静态？

  • 无构建步骤：直接打开 HTML 即可看，不需要 npm install / 打包。
  • 无敏感后端：所有数据处理在本地 Python 脚本完成，不上传原始轨迹数据到服务器。
  • GitHub Pages 原生支持：把文件推到仓库，Pages 自动 serving。

第一步：本地预览

不要直接双击 HTML 文件打开——那样浏览器会用 file:// 协议，导致相对路径和 JS 模块加载出错。 正确做法是起一个本地 HTTP 服务：

# 在项目根目录执行
python -m http.server 8767

然后在浏览器打开 http://localhost:8767，就能看到完整站点。想换端口，把 8767 改成别的数字即可。

📌
注意：原始轨迹数据（raw/ 目录）通常很大，已被 .gitignore 排除，不会进仓库。 网页里用到的图都放在 assets/img/ 和数据摘要放在 data/，这才是应该被 Pages 服务的内容。

第二步：初始化仓库并推送

如果你已经拿到整理好的项目文件夹，按下面命令推送到 GitHub：

# 进入项目根目录
cd C:\Users\wade\Documents\taxi

# 初始化仓库（如未初始化）
git init

# 添加并提交
git add .
git commit -m "init: structured taxi trajectory analysis site"

# 关联远程仓库
# 把 YOUR_USER/YOUR_REPO 换成你的 GitHub 用户名和仓库名
git remote add origin https://github.com/YOUR_USER/YOUR_REPO.git

# 推送 main 分支
git branch -M main
git push -u origin main

推送前可以检查 .gitignore 是否正确排除了大文件：

# 查看会被忽略的大目录
raw/beijing/
raw/shenzhen/
raw/wuxi/
*.rar
*.zip

第三步：启用 GitHub Pages

  1. 打开仓库设置

    在 GitHub 仓库页面点击 Settings。

  2. 进入 Pages 设置

    左侧菜单选择 Pages。

  3. 选择部署分支

    Source 选择 Deploy from a branch，Branch 选 main，文件夹选 /(root)，然后 Save。

  4. 等待部署

    GitHub 会在 https://YOUR_USER.github.io/YOUR_REPO 提供服务，通常几十秒到几分钟生效。

📌
部署后如何更新？ 每次修改 HTML/CSS/JS/图片后，执行 git add . && git commit -m "xxx" && git push， GitHub Pages 会自动重新部署。

部署前检查清单

检查项应该看到
首页路径index.html 在仓库根目录
相对路径所有页面用 ./、../ 引用，不用绝对磁盘路径
图片存在assets/img/ 下的 PNG 都正确生成并提交
无大文件raw/ 目录未被提交（检查 .gitignore）
本地可访问http://localhost:8767 能正常浏览所有页面

可选：绑定自定义域名

如果你有自己的域名，可以在仓库 Settings → Pages → Custom domain 里填写， 然后在 DNS 服务商添加一条 CNAME 记录指向 YOUR_USER.github.io。 首次绑定后，GitHub 会自动生成 HTTPS 证书，稍等几分钟即可生效。
